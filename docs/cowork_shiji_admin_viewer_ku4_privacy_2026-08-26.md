# Cowork タスク指示書: 管理者閲覧機能 区切り4（法務文言・privacy.html追記）

対象リポジトリ: `rakuten-kpi-app`（このファイルが置かれているリポジトリそのもの）。
このファイル1本だけ読めば作業できるように、背景から書く。

## 背景（このタスクだけを見る人向けの説明）

このプロダクト「ウレシル」は楽天出店者向けのKPI管理SaaS。オーナー（開発者）が導入オンボーディングや問い合わせ対応で顧客と会話しながら同じ画面を見て案内できるよう、「管理者閲覧機能」（専用の管理者アカウントが、顧客アカウントの画面を読み取り専用で見られる機能）を実装中。

実装計画書は `docs/jisso_keikaku_admin_viewer_2026-08-26.md`。このタスクはその計画書の「区切り4」に該当し、他の区切り（バックエンド実装・フロントエンド実装）とは完全に独立して進められる。**このタスクはLPの静的HTML1ファイルの追記のみで、アプリのコード（`backend/` `frontend/`）には一切触れない。**

閲覧機能そのものの実装が完了しているかどうかに関わらず、このタスクは先に進めてよい（法的な備えを機能より先に用意しておく方針）。

## やること

`lp/privacy.html`（プライバシーポリシー。静的HTML、ビルド工程なし、ブラウザで直接開いて確認できる）の **`<h2>6. 安全管理措置</h2>` セクション**に、以下の一文を新しい `<p>` として追加する。

追加する文言（確定済み・変更しないこと。オーナー自身が確定した文言）:

```
サポート対応および導入支援の目的で、当方の担当者が利用者の登録データを閲覧する場合があります。閲覧は必要な範囲に限り、閲覧記録を保存します。
```

具体的には、現在の該当箇所:

```html
    <h2>6. 安全管理措置</h2>
    <p>当方は、取得した情報への不正アクセス、紛失、漏えい等を防止するため、通信の暗号化（TLS）、アクセス権限の管理等の安全管理措置を講じます。</p>

    <h2>7. 開示・訂正・削除の請求</h2>
```

を、次のように変更する（既存の1文目はそのまま残し、2文目として追加する。1つの `<p>` にまとめて2文にしても、`<p>` を2つに分けてもどちらでもよいが、他の章の書き方（1章1〜2文のシンプルな `<p>` ）に合わせるなら1つの `<p>` に2文をまとめる形を推奨する）:

```html
    <h2>6. 安全管理措置</h2>
    <p>当方は、取得した情報への不正アクセス、紛失、漏えい等を防止するため、通信の暗号化（TLS）、アクセス権限の管理等の安全管理措置を講じます。サポート対応および導入支援の目的で、当方の担当者が利用者の登録データを閲覧する場合があります。閲覧は必要な範囲に限り、閲覧記録を保存します。</p>

    <h2>7. 開示・訂正・削除の請求</h2>
```

あわせて、ページ冒頭の改定日表記を今日の日付に更新する（このリポジトリの法的文書の慣例。`terms.html` 等も同じ形式）:

```html
    <p class="updated">制定日：2026年7月23日（最終改定：2026年7月29日）</p>
```
↓
```html
    <p class="updated">制定日：2026年7月23日（最終改定：2026年8月26日）</p>
```

## やらないこと（スコープ外）

- `lp/terms.html` / `lp/tokushoho.html` / `lp/help.html` / `lp/index.html` / `lp/about.html` は**一切変更しない**。このリポジトリには「解約文言は4ファイル同時に直す」という別の規約があるが、今回追加する文言は解約とは無関係（サポート対応時の閲覧についての説明）なので、その規約の対象外。
- `backend/` `frontend/` のコードには触れない。
- 文言そのものの変更・言い回しの調整はしない（確定済みのため、そのまま使う）。

## 検証

- ブラウザで `lp/privacy.html` を直接開き（ビルド不要）、6章に新しい文が表示されること、改定日が更新されていることを目視確認する
- HTMLの `<h2>` / `<p>` のタグ数・入れ子が壊れていないこと（差分がこのブロックだけに閉じていること）を確認する
- 他ページ（`terms.html` 等）からのリンク・導線に変更がないことを確認する（今回変更しないため差分ゼロのはず）

## 納品方法

このリポジトリの標準運用に従い、変更はブランチを切ってコミット → プッシュ → Pull Request を作成する（mainへの直接pushはしない）。GitHub連携で push・PR作成ができない環境の場合は、`main` からの累積差分パッチ（SHA256・対象ファイル一覧つき、`git apply --check` の手順を明記）をチャット上で提示する形に切り替える。

PRの説明文には「`docs/jisso_keikaku_admin_viewer_2026-08-26.md` の区切り4に対応」と明記すること。
