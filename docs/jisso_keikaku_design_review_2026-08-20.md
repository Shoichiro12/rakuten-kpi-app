## 2. 実装内容（区切り）

### 区切り1: GAP分析の選択KPI連動（決定1）
- `kpiGap.ts`: `gapDeltaFor(row, kpi|null)`（null=売上）と `orderByKpiGap(rows, kpi|null)` を追加。
  `orderBySalesGap` は `orderByKpiGap(rows, null)` の別名として残す。
  並び順注記も `orderNote(kpi, axis)` で選択KPIに応じて出す（基準を書かない並べ替えは出さない規約）。
- `GenreCards.tsx`: 並び順・「最大GAP」バッジ（選択時は「◯◯GAP最大」表記）を選択KPIに連動。
- `GapAnalysis.tsx`: 商品テーブルの既定順も選択KPIに連動。列ソートが常に勝つ関係は不変。
- CVRのGAPは pt、アクセス・客単価は変化率(%)で比較（既存 `gapKpiDelta` を使用）。

### 区切り2: ダッシュボード初期表示の圧縮
- アラートは最大3件表示、残りは `<details>`「他N件のアラート」に格納。
- 週次トレンド＋売上/利益/広告費推移の2グラフを `<details>`（既定畳み）へ。
- 売上予算プラン（RevenuePlanPanel）とアクセス逆算（AccessPlanner）を `<details>`（既定畳み）へ。
- 1層ヒーロー・今日やること・評価マトリクス・利益/広告投資4枚は現状維持
  （結論→次の行動→判断材料、の順）。

### 区切り3: 商品別KPIの一覧圧縮
- 一覧の列を「商品名 / 状態 / RPP売上（円） / ROI（%） / CPO（円） / 詳細」に圧縮
  （状態=CPO超過・ROI100%割れの課題バッジ。課題なしは薄い「良好」）。
- GP・GPR・CV・CVR・ROAS・Limit CPO は右の詳細パネルへ集約（パネルに売上・CV・CPO・Limit CPO を追加）。
- ソート（useTableSort）は残る列で維持。

### 区切り4: RPP広告実績の基準期間選択
- 「表示基準: 720h / 12h」のセグメント切替を期間タブの隣に追加（既定=720h。
  集計の正が720hであることは不変）。
- KPIカードは選択基準を主数値・もう一方を小さく併記（MiniKpiCardの主従を切替）。
- 売上カードは選択基準1枚＋比較の小行に統合。
- 商品別テーブルは選択基準の列のみ表示（12h選択時は12h列）。診断列は商品名の直後（既存位置）を維持。
- グラフの売上系列も選択基準に追従。

### 区切り5: データ取込み・目標設定・共通フォント
- データ取込み: 「個別に取り込む（①RPP・②商品分析）」「取込み済みデータの管理（履歴・削除）」を
  既存 `Collapsible` で折りたたみ（既定閉）。「まずは試してみたい方へ（サンプル）」は
  データ未取込のときだけ既定で開く。まとめて取込み・3ステップ・セットアップ進捗は現状維持。
- 目標設定: 「目標値の試算」ブロックをKGIカードの直下（同カード内）へ移動し、入力→結果の因果を接続。
- 共通フォント: `frontend/src` の `text-[10px]` / `text-[11px]` を `text-xs`(12px) へ一括引き上げ。
  （レビュー指摘＋既存規則2-2「本文・ラベル12〜14px」に整合）

### 区切り6: LP改修
- ヒーロー: 対象（RPP運用中の楽天店舗）・状況（ROASは見えるが利益が見えない）・
  成果（利益が残るかが毎週わかる）を冒頭で具体化。数値の新規主張は追加しない（捏造禁止）。
- 5工程: 決定6の強弱（2.0/4.0=画像つき主役、1.0/3.0/5.0=画像なし補助）。
- 書体: `--font-display` を Zen Kaku Gothic New へ（決定3）。ワードマークのみ Zen Maru 維持。
- 料金: プランカードに「ツールで自走したい方向け」、コンサルに「伴走がほしい方向け・別契約」を
  明記して境界を分離。
- CTA: 主CTA文言を「14日間無料で試す」に統一（nav / hero / 料金 / CTAバンド）。
- `style.css`（下層ページ）: ネイビー/赤トークンをC案トーン（紙色・墨色・セージ）へ寄せる。
- shot-hero.jpg 再撮影（決定5）。1.0/3.0の画像参照は外す（ファイルは残す）。
- 事例ストーリーはHTMLコメントで位置確保のみ（決定4）。
