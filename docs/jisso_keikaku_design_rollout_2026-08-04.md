## 1. 方針: 先に共通部品を作り、画面には貼るだけにする

画面ごとに書き換えると、必ず画面間でブレる（今回の `max-w` 騒動と同じ構造）。
**区切り0で「テイストの実体」をコードにして、各画面はそれを呼ぶだけにする。**

### 区切り0で作るもの（新規ファイル）

| ファイル | 中身 |
|---|---|

- 万円表記・pt表記・良い方向のフラグは**ロジックの修正**なので、見た目の好みに左右されずに進められる
- `format.ts` と `metrics.ts` ができた時点で、各画面の変更は「数値を関数に通す」だけになる

## 3. GAP分析が独特な点（調査結果）

`pages/GapAnalysis.tsx` 415行＋`components/gap/` 5ファイル 872行。他画面と構造が違うのは次の6点。

1. **3ステップのドリルダウンで画面の中身が入れ替わる。**
   ショップ全体 → ジャンル別 → 商品別。`step` / `selectedKPI` / `selectedGenre` / `selectedProduct` の
   4つの状態で表示が変わる。他画面は「期間を変えるだけ」なので性質が違う
2. **ロジックツリーが自前のSVG描画。** KGI → アクセス / CVR / 客単価 を枝で結び、
   達成率で緑（100%以上）・黄（80%以上）・赤（80%未満）に塗り分けている。
   Recharts ではないので、共通のチャート設定が効かない
3. **右サイドに常時アクションパネルがある2カラム構成。** 他画面は1カラム
4. **評価マトリクスとアクションサマリが同居**していて、情報の層が多い
5. **年次のときは診断系（マトリクス・サマリ・アクションパネル）を出さない分岐**がある
6. **アクセス軸（`rpp_click` / `site_uu`）が画面内で切り替わる。** 軸を混ぜない規約があるので、
   数値の見せ方を変えるときは軸の表示と必ずセットで考える必要がある

### GAP分析について確認したいこと → **3点ともオーナー承認済み（2026-08-04）**

**Q1. ロジックツリーのノードをどうするか → 案A（弾丸グラフ化）で承認**

現状は「達成率で3色に塗り分けた箱」です。3つの案があります。

- **案A: 各ノードを弾丸グラフにする**（推奨）。実績・目標・達成率が1本で読めて、ダッシュボードと同じ文法になる。
  ツリーの枝はそのまま残す
- 案B: 色だけ新しい状態色に差し替える。最小の変更だが、色で量を表す形は残る（知覚順位では最下位）
- 案C: ツリーをやめて、KGI→3指標を縦積みの弾丸グラフ4本にする。読みやすいが「ツリー」の構造は失われる

**Q2. 右サイドのアクションパネルの扱い → 案A（位置そのまま・中身だけ）で承認。**
VISIONの考え方には賛成だが、GAPは挙動が独特でリスクを重ねたくないため。区切り4を実画面で見てから、
必要ならその後の別チケットとして案Bを検討する

VISION.md には「出力の最終地点は数値ではなくアクション」と書いてあります。
であればアクションパネルは**今より強くする**のが筋ですが、現状は右の脇に置かれています。

- 案A: 位置はそのまま、中の見せ方だけ整える（安全）
- 案B: ステップごとの結論として本文側の上部に出し、右サイドは補足に降ろす（VISIONに忠実だが変更は大きい）

**Q3. ドリルダウンのUI自体を触るか → 案A（触らない）で承認**

- 案A: **触らない。** 見た目（数字・色・余白・表）だけ揃える（推奨。挙動が独特なぶんリスクが高い）
- 案B: ステップUIも含めて見直す

### 区切り5で分かったこと（2026-08-04）

対象2画面の数値表示は**全部で5箇所**しかなく、うち **format.ts に寄せられたのは2箇所だけ**だった。

| 箇所 | 対応 |

### 区切り4の表で分かったこと（2026-08-04・`0d2d5b0`）

規則4章の4点（`tabular-nums`・1px区切り・固定ヘッダー・左端固定）を入れる過程で、
**規則には書いていない実装上の前提が2つ**あることが分かった。他画面へ展開するときも同じ。

**(1) 固定ヘッダーは「表のラッパー自身が縦スクロールする」ことが前提**

ラッパーが `overflow-x-auto` だけの場合、CSS の計算値としては縦も `auto` になるが、
高さが無制限なので縦スクロールは発生しない。すると `sticky top-0` を書いても
ヘッダーは固定されず、ページ側のスクロールで枠ごと画面外に出ていく。
**`max-h-*` と必ずセットにする**（今回は `max-h-[70vh] overflow-auto`）。

⚠️ **区切り2で入れた `ProductKPI.tsx` / `RppAnalysis.tsx` の `sticky top-0` は
この前提を満たしておらず、実際には固定されていない。** 表示が壊れているわけではないので
緊急ではないが、直すには同じ `max-h` を付ける＝表の高さを制限する挙動変更になるため、
**別チケットとして切り出す**（2026-08-04）。

**(2) 左端固定の識別列には `min-w` が要る**

`min-w` が無いと、狭い幅のときに商品名と「母数不足・参考値」バッジが1文字ずつ折り返し、
行の高さが数百pxに膨らむ。固定した列が読めないと左端固定の意味がないので、
`min-w-[11rem]` を与えた。

また**浮く左端セルには行と同じ背景を明示的に持たせる**こと。持たせないと横スクロールした
右の列が下から透けて見える。`bg-inherit` は Tailwind の出力順に依存して崩れるので使わず、
`tr` に `group` を付けてセル側を `group-hover:` で追随させる。

ついでに**行背景を「警告 > 選択 > 通常」の1本の三項に統一**した。従来は `bg-blue-50`（選択）と
`bg-red-50`（Limit CPO超過）が別々の三項で並んでおり、両方立つ行の勝敗が
Tailwind の出力順任せだった。

**単位は見出しに寄せていない。** セル側の `formatCurrency` / `formatPercent` が `¥` と `%` を
出しているため、見出しに単位を足すと二重表記になる。寄せるならセルを `lib/format.ts` に
差し替える別作業。
