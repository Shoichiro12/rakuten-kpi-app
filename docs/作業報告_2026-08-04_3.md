## 見つけて直した欠陥

### (1) 4つのエンドポイントが別々の条件でアクセス軸を決めていた（影響度: 中）

- 症状: 1つの画面の中で、ロジックツリーだけ site_uu なのにジャンル別内訳は rpp_click、という混在が
  起こりうる状態だった。要件No.5「同一画面で両軸を混在させない」に正面から反する
- 原因: `kpi-tree` / `shop` / `genre` / `product` の4本が、それぞれ独自に
  「商品分析データがあるか」を判定していた。しかも条件が微妙に違う
  - `kpi-tree` … `get_shop_monthly()` の戻り（廃盤除外の指定なし）
  - `shop` … `get_shop_monthly(exclude_management_nos=廃盤)` の戻り
  - `genre` … `MonthlyItemSales` の行。**廃盤除外を適用したあと**に空かどうかを判定
  - `product` … `MonthlyItemSales` の行。**廃盤除外を適用する前**に空かどうかを判定
- どう出るか: 「廃盤を除外」にチェックを入れて、そのジャンル・期間の商品が全部廃盤だった場合、
  `genre` だけ RPP軸に落ちてツリーと食い違う
- 対応: 判定を `gap_analysis.uses_shop_axis()` の1関数に集約。
  **廃盤除外は軸判定に混ぜない**（絞り込みで0件になるのは「データが無い」ではないので軸は変えない）を規約にした。
  あわせて `/api/gap/shop` が `access_axis` を返していなかったので全レスポンスに追加

### (2) 週次の目標比較が二重に間違っていた（影響度: 中〜大）

- 症状その1: **同じ画面の中で売上達成率が2つあった。** ロジックツリー 14.8% と 評価マトリクス 65.8%
- 原因その1: 評価マトリクス（`evaluation.py`）は月次目標を日割り按分（×7÷当月日数）してから比べているのに、
  ロジックツリー（`gap_analysis.py`）は按分せず月次目標とそのまま比べていた
- 症状その2: アクセス達成率 6.5%、CVR達成率 224.7% という数字が出ていた
- 原因その2: 目標は「アクセス目標（UU）＝月間ユニークユーザー数」＝サイト全体・月次の定義。
  一方で週次の実績は RPP広告クリック基準。**期間も母数も違うものを割り算していた**。
  CVR も週次はクリック基準（3.37%）で、UU基準の目標（1.5%）と比べると 224.7% と「達成」に見えるが、
  同じ月をUU基準で見ると 1.94% で 129% になる
- 対応: **オーナー決定で、週次は目標比較を出さないことにした。**
  バックエンドが `target_comparable: false` を返し、フロントは達成率・目標線・GAPを描かず
  「週次は目標比較なし」と表示する。「目標未設定」と誤解されないよう、ツリーの下に理由の注記を出す

実測値（対象: 2026-08-02週・サンプルデータ）:

| アクセス 達成率 | 6.5% | 28.9% | 出さない |

## 注意点・申し送り

1. **新しいGAP系エンドポイントを足すときは、軸を `uses_shop_axis()` で判定すること。**
   自前で「商品分析データがあるか」を書かない。今回の(1)はまさにそれが4箇所に散った結果です
2. **廃盤除外を軸判定に混ぜないこと。** 絞り込んだ結果0件になるのは「データが無い」ではありません
3. **週次に達成率を戻さないこと。** 戻すなら週次専用の目標（RPPクリック基準）を持つところからです
4. **ジャンルカードに軸バッジを戻さないこと。** 画面ヘッダーに1つだけ、が決定です（同じバッジが3つ並ぶため移設）
5. `kpi-tree` は他の3本と違って `include_inactive` パラメータを持っていません。
   つまり**「廃盤を除外」のチェックはツリーの数字には効きません**（既存の挙動・今回は変えていない）。
   軸の判定は揃えたので混在は起きませんが、数字の粒度としては不揃いです。気になるなら別チケットで
