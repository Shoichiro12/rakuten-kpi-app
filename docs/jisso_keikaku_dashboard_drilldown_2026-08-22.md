# 実装計画: ダッシュボードのドリルダウン再設計（診断フロー化） 2026-08-22

チャットでのデザイン検討（モックv1〜v5＋制約なし案）を経て確定した方向性を、
本体アプリ（`frontend/` 中心）に実装する計画。利用者ゼロの期間のため、
フィーチャーフラグや段階公開は行わず main に直接進める（オーナー方針 2026-08-22）。

添付モック: `ureshiru_dashboard_proposal_v5.html`（確定版・不足額表示入り）。
参考として v1〜v4 と制約なし案（診断書コンセプト、不採用）もチャット成果物にあり。

---

## 0. 確定した方向性（デザイン検討の結論）

1. **ダッシュボード＝ドリルダウンの入口にする。** 開いた瞬間に見えるのは「予算 vs 売上」だけ。
   達成していれば何も足さない。未達のときだけ「詳しく見る」で下に掘れる
2. **掘る順序**: 予算vs売上 → アクセス/CVR/客単価 → ジャンル（大/中/小切替）→ 商品 → アクション提案。
   判定・並び順・機会損失・打ち手のロジックは**現行GAP分析のものを流用**し、見せ方だけ変える
3. **達成率だけでなく不足額（¥）を明示する**（達成時は超過額）
4. **視覚言語**: 白カード＋細罫線＋影ほぼなし。色ピルは「達成/未達」「最優先」の2箇所のみ。
   一覧はGitHubのIssue行の文法（太字タイトル＋グレー補足行・罫線区切り・ホバーで薄色）。
   絵文字アイコン禁止・単色線アイコン（lucide）に統一
5. **フォント**: 本文 BIZ UDPGothic / 数値 Inter（tabular-nums）。アプリ全体で1+1書体に統一
6. **配色**: LPのC案トークン（生成り×セージ×墨色）をアプリへ展開。サイドバーは紺→墨色
7. 判子・明朝など「診断書」案の和風表現は**不採用**（主要ユーザー層＝女性の店長・運営プレイヤーに
   合わない、というオーナー判断）。移植したのは不足額表示のみ
8. サイドバーの開閉は**既存の承認済み仕様のまま**（2026-08-03: トグル上部・幅切替は即時・
   折りたたみ時はCSSツールチップ）。配色だけ差し替える

## 3. 画面仕様（5段）

**共通**: 各段は前の段で選択して初めて出現（段階表示）。上部パンくずに軌跡を常時表示。
期間切替（週次/月次/年次）は現行どおりヘッダー右。段を掘った状態で期間を変えたら全段リセットして1段目へ。

| 段 | 表示 | データ | 遷移条件 |
|---|---|---|---|
| 1 予算vs売上 | 実績・目標・弾丸グラフ・達成率・**不足額/超過額**・状態ピル（達成/未達） | 現行KGIヒーローと同一 | 未達なら「詳しく見る」。達成なら既定では何も出さない（確認事項Q5） |
| 2 要因 | 最悪KPIを左赤罫の主カードで立て、残り2つは細い行。達成KPIは薄く・遷移不可＋「達成」表記 | 現行3分解と同一 | 未達KPIをクリック |
| 3 ジャンル | 粒度切替（大/中/小 = level u1/u2/u3）。行=ジャンル名＋商品数＋選択KPI実績＋前期比＋機会損失。悪い順 | `/api/gap/genre` | ジャンル行クリック（parent引き継ぎで下位粒度にも潜れる） |
| 4 商品 | 行=商品名＋管理番号＋基準割れ注記＋主要3指標。悪い順 | `/api/gap/product?genre=` | 商品行クリック |
| 5 アクション | 最優先1件（大カード: 施策名・理由・想定効果・追加費・所要・実施ボタン）＋副施策の行（担当先つき） | 既存アクションロジック | 「実施した」で既存の実施記録に接続 |

**SKU段は初期リリースに含めない。** データが管理番号（商品）粒度のため（`MonthlyItemSales` /
`RppWeekly` とも management_no が最小単位）。SKU対応はデータ取込みの拡張が必要な別チケット。

## 5. 確認事項 → **5点ともオーナー承認済み（2026-08-22・すべて推奨案で確定）**

**Q1. GAP分析ページの扱い → 案A で承認**
- 案A: 新ダッシュボード稼働後も当面残す（機能重複を許容。落ち着いたら削除判断）← **承認**
- 案B: 区切り4でメニューから外す（コードは温存）
- 理由: 新ドリルはGAPのロジック流用なので数字は一致するが、評価マトリクス等の詳細表示は
  新ダッシュボードに載せない。詳細が要る場面が残るかを実運用（オーナー自身の利用）で見てから決めたい

**Q2. 旧ダッシュボード要素の行き先 → 両方とも案A で承認**
- 「今日やるべきこと」: 案A=撤去（段5のアクションが後継。件数バッジだけ段1に残す）← **承認** / 案B=下部に折りたたみで残す
- 推移グラフ・計画パネル: 案A=下部に折りたたみで残す（現行の`<details>`圧縮を踏襲）← **承認** / 案B=レポート出力へ移設

**Q3. 達成時の表示（段1）→ 案B で承認**
- 案A: 完全に何も出さない（モックどおり）
- 案B: 「達成していますが内訳を見る」の薄いリンクだけ残す ← **承認**（達成時でも掘りたい時があるため）

**Q4. ワードマークの書体 → 案A で承認**
- 案A: サイドバーの「ウレシル」もBIZ UDPGothicに統一（アプリ内は完全1書体）← **承認**
- 案B: ワードマークだけLPと同じZen Maru Gothicを維持
- ※ LP側の書体（Zen Kaku Gothic New見出し）は今回触らない。アプリとLPで本文書体が違う状態は許容

**Q5. 週次の目標按分 → 案A で承認**
- 段1の「不足額」は週次では按分目標に対する不足になる。按分方法は現行KGIヒーローの実装に従う
  （変更しない）。表示ラベル: 案A=「目標（週按分）」と明記する ← **承認** / 案B=現行どおり

## 7. リスク・注意

1. **軸の整合。** 週次=RPPクリック、月次=商品分析UU。段2で選んだKPIの軸が段3・4でも同じであること。
   `gap_analysis.py` の月次優先ロジック（商品分析があればUU軸）に段1〜5すべてが従う。
   検証は 2026-08-20 と同じ手法（APIの生値から期待順を計算してUI表示順と照合）
2. **粒度切替とparentの整合。** 大→中→小と潜るとき parent キーの前方一致が要。既存API仕様どおりだが、
   「中分類で見る」に切り替えた直後の選択状態リセットを仕様化する（切替時は選択解除）
3. **フォントのFOUT。** Google Fonts読み込み前にシステム書体で一瞬描画される。`display=swap`のまま許容
   （業務ツールなので体感優先）。気になる場合は後日セルフホストの別チケット
4. **区切り0の影響範囲。** トークン差し替えは全画面に及ぶ。既存の `rakuten-red` 16箇所は
   sage-deep もしくは ink へ置換（サイドバーのアクティブ表示は sage）。目視は全9画面ざっと見る
5. **色の二重定義を作らない。** 画面ごとの生hex直書き禁止。必ずTailwindトークン経由
   （2026-08-04診断の課題A/Fの再発防止）
6. モック（v5 HTML）はあくまで見た目の正。実装はReact＋Tailwindで書き直す。HTMLからのコピペはしない
