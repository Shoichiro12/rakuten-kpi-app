## 実装の中身

### 並び順（③）

ジャンルカードも商品テーブルも、**常に売上の前期比が悪い順**です。選択KPIでは切り替えません。
実装は `kpiGap.ts` の `orderBySalesGap()` 1本に集約してあり、**関数がKPIを引数に取らないのは意図的**です。

基準は「目標比」ではなく「前期比」。調べたところ **ジャンル・商品の階層には目標値がありません**
（`/api/gap/genre` と `/api/gap/product` は目標を返さない。アイテム別目標は商品単位の任意入力で
全商品を覆っていない）。目標が無いのに「目標比で並べています」とは書けないので、
前期比で並べたうえで**画面にその基準を明記**しました。
目標比で並べたいなら、GAP APIに目標値・YoY集計を足す別チケットになります。

列見出しソート（`useTableSort`）との関係は「既定順 → 列ソート」の順に適用。
ユーザーが列を選べばそちらが勝ち、3回クリックで解除すると売上GAP順に戻ります。

### カードの主役指標（②）

4指標（売上・CVR・客単価・ROAS）は消さず、**カード内の主役スロットを選択KPIに差し替える**形です。
アクセスを選べばアクセスが主役に立ち、売上は補助行に降ります。サイズは `Stat` の `default`（22px）。
hero（40px）にしない理由は、規約（`docs/ui_number_and_chart_rules_2026-08-04.md` 2-1）が
「大きい数字は1画面に1つ、多くて2つ」としており、横に並ぶカード全部を hero にすると衝突するためです。

あわせて、ジャンルカードの数値を `lib/format.ts`（万円表記）と `components/kpi/{Stat,Delta}` に
載せ替えました。区切り4のGAP分析はロジックツリーだけ弾丸グラフ化されていて、
ジャンルカードは旧 `lib/utils` のままだったためです。これで**CVRの前期比が pt で出る**ようになりました。

### 打ち手（①）

**この画面の打ち手の表示先は2箇所だけです。**

1. 上部の評価マトリクスのカード（`matrix_actions.py` 由来・未達KPIから機械的に決まる）
2. 商品を1つ選んだときの右サイド `ActionPanel`（4Pの具体タクティクス）

3つ目を足すのは不採用になりました。`GapAnalysis.tsx` の該当箇所にその旨のコメントを置いてあります。

  売上3分解のうち客単価だけ列が無かった

  ただし列は残してあります（売上3分解のうち客単価だけ列が無いのは元々おかしいため）。
  **不要なら1行で外せます。**

1. **並び順を「選択KPI基準」に戻さないこと。** `orderBySalesGap()` がKPIを引数に取らないのは意図的です。

2. **この画面に3つ目の打ち手の表示先を作らないこと。** 表示先は評価マトリクスのカードと
   右サイド `ActionPanel` の2箇所だけ、が決定です（①）。`GapAnalysis.tsx` にコメントを置いてあります
3. **ジャンルカードの主役数値を hero にしないこと。** 規約の「大きい数字は1画面に1つ」と衝突します（②）
4. **`ACTIONS` の `key` を変えないこと。** 実施チェックの保存（`ActionLog.action_key`）と対応しているため、
   変えると過去のチェックが外れます（切り出し時も一切変更していません）
5. **バックエンドの `matrix_actions.py` の `ACTION_LIBRARY` と、フロントの `actionLibrary.ts` は別物です。**
   前者は「店舗・期間の総合評価に対する要約アクション」、後者は「4Pの具体タクティクス」
6. 商品テーブルの列を1つ増やしたので、横スクロールの余裕がその分減っています。
   画面幅の規約上は「8列以上は全幅のまま」で変更なしです
