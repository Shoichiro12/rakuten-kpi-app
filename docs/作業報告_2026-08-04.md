## 実装の中身（決めたこと）

オーナー承認済みの3点。

1. **折りたたみ時のラベル補完は `title` 属性を使わず CSS の自作ツールチップ。**
   `title` は表示まで1〜2秒かかるうえ、キーボードフォーカスでは出ない。折りたたみ時は
   ラベルが唯一の手掛かりなので、Tab移動中に何も分からなくなるのが致命的だった。
   `group-hover` に加えて `group-focus-visible` でも出す。ツールチップ自体は `aria-hidden` で、
   読み上げ用の名前は `aria-label` が担う（二重読み上げの回避）
2. **トグルは上部ロゴ行の右端**、lucide の `PanelLeftClose` / `PanelLeftOpen`
3. **幅のアニメーションは入れない（即時切替）。** `width` のトランジションは毎フレーム
   レイアウト再計算が走り、商品マスタのような重いテーブルを右に抱えるとカクつく

ついでに入れたもの（承認済み）: 全ナビ項目の `focus-visible` リング、`touch-manipulation`、
ラベル span の `min-w-0`。いずれも web-design-guidelines のレビュー結果を反映したもの。

## 自分が作り込んだ副作用（オーナー指摘で判明）

依頼外で見つけたバグではなく、**今回の変更が原因で自分が作った問題**なので独立して書く。

### 1. サイドバーを畳んでも本丸の画面が広がらなかった（影響度: 中）

- 症状: サイドバーは 224px から 64px に縮むのに、商品マスタのテーブルは相変わらず
  横スクロールが必要。左側に大きな余白ができるだけだった
- 原因: 商品マスタ（`MasterSettings.tsx`）と目標設定（`TargetSetting.tsx`）の2画面だけ、
  ページ直下のコンテナが `max-w-4xl mx-auto`（896px）で頭打ちだった。しかも `mx-auto` で
  中央寄せなので、**サイドバーを縮めた160pxはそのまま左右の余白に吸われる**
- なぜ気づかなかったか: ダッシュボード・GAP分析・商品別KPI・RPP広告実績には上限が無く
  元から全幅だったので、「アプリ全体が全幅」という前提で実装してしまった。
  指示書に「商品マスタのテーブルで横スクロールが必要」と書いてあったのに、
  サイドバー側だけ見て受け側の画面を確認していない
- 対応: 2画面の `max-w-4xl mx-auto` を削除して他の4画面と同じ全幅に統一（`60bedd4`）
- 根拠: 本番配信中のバンドルに `max-w-4xl mx-auto` の文字列が存在しないことを確認済み

### 2. 全幅化で年間目標プランナー表が間延びした（影響度: 小）

- 症状: 目標設定の年間目標プランナー表が画面いっぱいに引き伸ばされ、月と数値の間が
  離れすぎて読みづらくなった
- 原因: この表は `w-full` で、サマリ表示だと5列しかない。親を全幅にしたので
  そのぶん列間が開いた。1件目の対応の副作用
- 対応: 表そのものに上限幅を持たせた（サマリ=`max-w-2xl` / 詳細=`max-w-5xl`）。
  数値の桁位置を揃える `tabular-nums` と、周辺の注記3箇所に `max-w-3xl` も追加（`af1105e`）

### 3. ファイル転送時に空行が1行入った（影響度: 小・コミット前に解消）

- Cowork のコンテナから Windows 側へ `Sidebar.tsx` を分割書き込みした際、チャンクの
  継ぎ目に空行が1つ余分に入った
- 検知: 改行コードを揃えたうえで MD5 を突き合わせたところ不一致（269行 vs 268行）
- 対応: 該当箇所を修正して MD5 一致を確認してからコミット。**リポジトリには入っていない**

## 注意点・申し送り

CLAUDE.md の申し送り表に1行追加済み。特に壊しやすいのは次の3点。

1. **ページ直下のコンテナに `max-w-*` を戻さないこと。** 戻すとサイドバー折りたたみの
   意味が無くなる。今回まさにそれで指摘を受けた
2. **ただし表・注記など個々のブロックの上限幅は別。** 全幅化の副作用への対策として
   意図的に入れている。「全幅にすると決めたのに `max-w` があるのはおかしい」と
   消さないこと。対象は年間目標プランナー表（`max-w-2xl` / `max-w-5xl`）と
   その周辺の注記3箇所（`max-w-3xl`）
3. **サイドバーの幅にトランジションを付けないこと。** 「ふわっと動かしたい」という
   要望は出ていない（オーナーに明示確認済み）。再浮上しても入れない。理由は
   `width` のアニメーションが毎フレーム再レイアウトを起こすため

その他:

- 折りたたみ状態は `localStorage` の `ureshiru:sidebar-collapsed`。ブラウザごとに保持なので、
  別のPCやシークレットウィンドウでは展開状態から始まる（仕様）
- `aside` に `overflow-hidden` を付けないこと。ツールチップがサイドバーの外へはみ出す作りのため
- デザインスキル（`web-design-guidelines` ほか）は gitignore 済みで、新しい環境では
  `npx skills add vercel-labs/agent-skills` で再導入が必要（既存の取り決めどおり）
- 今回はDB・モデル・APIに一切触っていないので、RLS・マルチテナントまわりへの影響は無い
