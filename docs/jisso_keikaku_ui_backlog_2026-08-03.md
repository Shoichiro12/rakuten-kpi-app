## 1. テーブルのソート機能

### 現状

テーブルを持つ画面は5つ。**列見出しソートはどこにも無い**（固定順のみ: RPPは広告費降順、マスタは管理番号順）。

| 画面 | テーブル | 列数 | 既存の絞り込み |
|---|---|---|---|
| 商品別KPI（ProductKPI） | 商品別KPI一覧 | 9列（RPP売上/GP/GPR/CV/CVR/ROAS/CPO/LimitCPO/ROI） | ジャンル・廃盤表示 |
| RPP広告実績（RppAnalysis） | 商品別週次実績 | 10列 | あり |
| GAP分析（GapAnalysis） | 商品別テーブル | 7列前後 | 階層ドリルダウン |
| 商品マスタ（MasterSettings） | 商品一覧 | 複数 | あり |
| 目標設定（TargetSetting） | アイテム別目標 | 6列 | 検索・ジャンル・未設定のみ（今回実装分） |

### 方針

- **共通フック `useTableSort` ＋ 共通見出しセル `SortableTh`** を新設（`components/table/`）。見出しクリックで 降順→昇順→解除 をトグル、矢印インジケーター表示。
- **ソートはフロント側で実施**。全画面とも一覧データは全件クライアントに来ているため、API変更は不要。
- **フィルターとの共存**: 絞り込み後の配列にソートを適用するだけ（`filtered → sorted` の順でメモ化）。既存フィルターには触らない。
- null/未設定値は昇降どちらでも**常に末尾**（「データ無し」が上位に来て邪魔になるのを防ぐ）。
- 適用対象は上記5画面すべてを推奨（Q5）。まず商品別KPI・RPP・GAPの3画面（指示書明記分）を先行し、マスタ・アイテム別目標は同じ部品を貼るだけなので同一区切り内で続けて適用。

## 2. 期間区分「年次」＋期間切り替えUIの作り直し

### 現状

- `PeriodSelector.tsx`（共通コンポーネント）＝ 週次/月次トグル ＋ 前後矢印 ＋ 生の date/month input。使用画面はダッシュボード・GAP分析・商品別KPI・レポート出力の4つ。状態は共通フック `usePeriodState`（data-statusから「データのある最新期間」を初期値採用）。
- バックエンドは `period: Literal["weekly","monthly"]` が広範囲（dashboard / gap_analysis / evaluation / products / rpp_diagnosis / export / recommendations 等）。

### 「分かりにくい」の正体（調査からの診断)

1. **今どの期間を見ているかのラベルが無い**。週次でdate inputに任意の日付（水曜など）が選べてしまい、内部では日曜起点の週に丸められるため、表示と実際の集計期間がずれて見える。
2. 前後矢印とinput直打ちが並んでいて、どちらが正なのか迷う。
3. 「データのある最新期間」へ戻る手段が無い（初期表示だけ賢いが、動かした後に戻れない）。

### 方針

**UI刷新（全画面共通のPeriodSelectorを作り直し）**:

- セグメント［週次｜月次｜年次］＋ 期間ナビ「◀ 2026/8/2〜8/8 ▶」形式。**期間ラベルを常に「実際の集計期間」で表示**（週次は日曜起点の週の範囲、月次は年月、年次は年）。
- ラベルクリックでピッカー（週=週選択、月=month input、年=年選択）。生inputの直打ちを主導線から外す。
- 「最新データへ」ボタンを追加（data-statusの最新期間へジャンプ）。
- `usePeriodState` を `Period = 'weekly' | 'monthly' | 'yearly'` に拡張。

**年次のスコープ（Q1・重要）**: バックエンドの期間分岐は影響範囲が広いので、**年次は「表示系」だけに絞る**ことを提案。

- 対象: ダッシュボードKPI集計・GAP分析・商品別KPI・レポート出力（＝PeriodSelectorを使う4画面）
- 集計: 年次 = 対象年のMonthlyItemSales/RPP実績の合算（率系は分子分母を合算してから再計算。月次の単純平均にしない）
- 前年比: 前年の同集計
- **対象外（月次のまま）**: 診断・アラート・改善提案・評価マトリクス系。母数ゲート（月430UU）や改善判定が月次前提で設計されており、年次に安易に広げると閾値の意味が壊れる。年次表示中はこれらのパネルに「診断は月次で行います」の注記を出す
- 年次の「目標」（Q2）: `shops.annual_sales_budget`（年間売上予算）と突き合わせる案を推奨。予算未設定なら月次targetsの合算をフォールバック。予算年度起点（budget_year_start_month）をどう扱うかが論点で、**シンプルに「暦年（1〜12月）」を年次と定義し、予算年度は年間目標プランナー側の役割のまま**とする案を推奨（年次表示にまで年度起点を持ち込むと複雑になりすぎる）

## 3. ダッシュボードの情報整理・優先度付け

### 現状の棚卸し

上から順に: 今日やること / 施策の結果 / 評価マトリクス＋改善アクション / 売上予算プラン / アクセスプランナー / 改善重要アラート / 店舗全体の実績（ヒーロー4枚）/ 主要KPI（4枚）/ 効率指標（**8枚**）/ 参考指標（4枚＋）/ 週次トレンドグラフ。

**KPIカードが約20枚＋パネル6個**。全部が同じ強さで並んでおり、「売上目標に対して今どうで、何をすべきか」という主題が埋もれている。指摘どおり。

### 方針（すり合わせ用に2案。Q3）

**案A「今日の判断ファースト」（3層の強弱付け）** ← 推奨

1. **1層目（ヒーロー）**: KGI達成状況を1ブロックに統合。売上実績 vs 目標・達成率・着地見込みを大きく1枚＋売上3分解（アクセス/CVR/客単価）を並列。ここだけ見れば店の今が分かる
2. **2層目（行動）**: 今日やること・改善アラート・評価マトリクスを「アクション帯」として集約（重複気味の3パネルの見せ方を整理）
3. **3層目（詳細・折りたたみ)**: 効率指標8枚・参考指標は**アコーディオン（既定で畳む）**へ。トレンドグラフ・売上予算プラン・アクセスプランナーはこの層
- 変更は主に配置と強弱で、データ取得・計算は触らない。リスク低

**案B「グラフ主導」**

- 数値カードはKGI＋3分解の4枚だけ残し、効率指標・参考指標は**コンパクトな表1ブロック**に圧縮。トレンドは各カードにスパークライン内蔵
- 視覚的にはより締まるが、カード→表・スパークライン追加で工数は案Aより大きい

**推奨は案Aベース**で、案Bの「効率指標を表に圧縮」だけ取り込むハイブリッド。datavizスキルの視覚階層の指針（強調は1点・その他は沈める）に沿う。2章の期間UI刷新と同じ区切りでダッシュボードを触ると、レイアウト変更が一度で済む。
