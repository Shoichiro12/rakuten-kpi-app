## 実装した内容

### アプリUI
1. **GAP分析の選択KPI連動**（`kpiGap.ts` / `GenreCards.tsx` / `GapAnalysis.tsx`）
   - `orderByKpiGap(rows, kpi|null)` を追加。並び順＝選択KPIの前期比が悪い順（未選択は売上基準）
   - 「最大GAP」バッジは並び順と同じ基準で判定し、「売上GAP最大」「転換率GAP最大」のように基準を明示
   - GAPが悪化していない（前期比プラス）ときは最大GAPを強調しない
   - 並び順注記は `orderNote()` で選択KPIに追従（CVRは「差はpt」も明記）
2. **ダッシュボード初期表示の圧縮**（`Dashboard.tsx`）
   - アラートは上位3件＋「残りN件を表示」の開閉
   - 週次トレンド・売上/利益/広告費推移の2グラフを `<details>`（既定畳み）へ
   - 売上予算プラン・アクセス逆算を `<details>`（既定畳み）へ。年次は計画ブロックごと非表示
3. **商品別KPIの一覧圧縮**（`ProductKPI.tsx`）
   - 一覧＝商品名 / 状態（CPO超過・ROI100%割れバッジ、課題なしは薄い「良好」）/ RPP売上 / ROI / CPO / 詳細
   - 詳細パネルに RPP売上・CV・CPO・Limit CPO を追加し全12指標を集約（表とパネルの二重表示を解消）
4. **RPPの表示基準選択**（`RppAnalysis.tsx`）
   - 「表示基準 720h / 12h」トグル（既定720h）。KPIカードは主従、売上カードは1枚＋比較行、
     商品表は選択基準の列のみ、グラフの売上系列も追従
5. **データ取込みの折りたたみ**（`DataImport.tsx`）
   - 個別取込（①②・貼り付け）と取込み済みデータ管理（履歴・個別削除）を既定畳みの `<details>` へ
   - サンプル生成はデータ未取込のときだけ既定展開（`key` 切替でリセット）
6. **目標設定**（`TargetSetting.tsx`）: 「この目標のときの試算」をKGIカード内・入力直下へ移動
7. **共通フォント**: `text-[9px]/[10px]/[11px]` を全て `text-xs`(12px) へ（28ファイル）

## 検証結果（すべてローカル実画面・ヘッドレスChromium）

- `npm run build` 型エラー0 / `from main import app` OK / アプリ主要5画面でコンソールエラー0
  （Google Fontsへの外部接続エラーはサンドボックスの通信制限によるもので除外）
- **GAP並び順の照合**: `/api/gap/product`（月次・11商品）の生値から期待順を計算し、
  access / cvr / av の3通りとも**UIの表示順と完全一致**（3通りで並びが実際に異なることも確認）。
  並び順注記の文言切替（「アクセス（UU）の前期比が悪い順」等）も確認
- ダッシュボード: 推移グラフ・計画パネルの `<details>` が既定closed、アラートは3件以下のため
  展開UIは非表示（仕様どおり）
- 商品別KPI: ヘッダー6列（商品名/状態/RPP売上/ROI/CPO/詳細）、詳細パネルに12指標
- RPP: 基準トグルで表ヘッダーが 720h系5列 ⇄ 12h系5列 に切替、売上カードのラベルも追従
- データ取込み: 個別取込・データ管理とも既定closed、サンプルはデータあり状態でclosed
- 目標設定: 「この目標のときの試算」がKGIカード内に存在
- LP: 375px / 1280px とも横オーバーフロー0、CTA4箇所すべて「14日間無料で試す」、
  h1=Zen Kaku Gothic New・ワードマーク=Zen Maru Gothic、工程の主従（sub/img）が設計どおり、
  terms.html の body 背景 #fdfcf9・文字 #383731・h2罫 #78927b（C案トーン反映）
